# luci-app-warp-autocheck — дизайн

## Зачем

WARP-конфиг (`/root/WARP.conf`), сгенерированный Zapret Manager (кнопка
«Сгенерировать с проверкой» в разделе AmneziaWG), со временем умирает: провайдер
закрывает точку входа, DPI начинает рвать туннель, Cloudflare отправляет трафик
через российский узел. Сейчас пользователь должен сам заметить проблему и руками
перегенерировать конфиг.

Этот пакет делает то же автоматически: периодически проверяет работоспособность
текущего WARP-конфига и, если тот перестал работать, сам генерирует новый с
подбором рабочей точки входа (та же логика, что у кнопки «Сгенерировать с
проверкой» в Zapret Manager) и переприменяет конфиг.

Отдельный пакет, от Zapret Manager зависит только духом, не кодом: своя копия
логики проверки и генерации.

## Сценарий (главный use-case)

1. У пользователя OpenWrt-роутер, установлены AmneziaWG и Zapret Manager,
   WARP-конфиг сгенерирован («Сгенерировать с проверкой») и импортирован как
   amneziawg-интерфейс.
2. Пользователь ставит `luci-app-warp-autocheck`, открывает страницу LuCI
   (меню «Службы → WARP AutoCheck»).
3. Если `/root/WARP.conf` не существует — страница показывает ошибку
   «WARP-конфиг не найден. Сгенерируйте WARP-конфиг в Zapret Manager (раздел
   AmneziaWG)» и на этом функциональность заканчивается (автопроверку включить
   нельзя).
4. Если конфиг есть — страница показывает:
   - статус последней проверки (когда, результат: работает / нет связи /
     обрывается DPI / российский узел / заменён);
   - текущую точку входа из WARP.conf;
   - имя интерфейса AmneziaWG (настраиваемое, по умолчанию `warp`);
   - переключатель автопроверки (вкл/выкл);
   - интервал автопроверки в часах (по умолчанию 6, настраивается);
   - кнопку «Проверить сейчас» — ручной запуск той же проверки;
   - кнопку «Заменить сейчас» — ручной запуск генерации с проверкой;
   - хвост лога (последние операции).
5. По cron (каждый час просыпается, проверяет, не прошло ли N часов) запускает
   проверку: trace-запросы через интерфейс. Если проверка не прошла —
   повторяет её ещё до 2 раз с интервалом ~5 минут (защита от ложных
   срабатываний). Если конфиг стабильно мёртв — запускает генерацию с
   подбором, пишет новый WARP.conf и перезапускает интерфейс.

## Цели / не-цели / анти-цели

**Цели:**
- автономный ipk-пакет (opkg для OpenWrt 24.10, apk-совместимость для 25.12+)
  + возможность поставить установочным скриптом;
- страница LuCI (русский интерфейс): статус, настройки, ручные кнопки;
- автопроверка по расписанию с защитой от ложных срабатываний;
- автозамена нерабочего конфига генерацией с подбором точки входа и маски;
- автоматический перезапуск интерфейса после замены;
- лог операций и статус последней проверки.

**Не-цели:**
- не трогаем конфигурацию интерфейса (имя, firewall-зона, маршруты остаются
  как были) — заменяется только содержимое WARP.conf + endpoint/ключи в
  интерфейсе;
- не дублируем остальной функционал Zapret Manager (создание интерфейсов,
  редактор конфига и т.д.);
- не поддерживаем случаи «конфиг используется Mixomo/Steer» — только сценарий
  «конфег импортирован как amneziawg-интерфейс».

**Анти-цели (что было бы провалом):**
- ложная замена рабочего конфига из-за одного сбоя сети;
- замена, ломающая интерфейс (например, запись битого конфига при выключенном
  роутере посреди записи);
- зависимость от конкретной версии Zapret Manager (вызовы его функций).

## Архитектура

Копия паттерна Zapret Manager (он проверен на OpenWrt 24.10+):

```
usr/libexec/rpcd/warp-autocheck        # rpcd-плагин: методы для LuCI + запуск действий
usr/share/rpcd/acl.d/luci-app-warp-autocheck.json   # ACL
usr/share/luci/menu.d/luci-app-warp-autocheck.json  # пункт меню
www/luci-static/resources/view/warp-autocheck/*.js  # страница (JS view)
etc/init.d/warp-autocheck              # инициализация cron-строки / чистка
etc/config/warp-autocheck              # UCI-конфиг
usr/bin/warp-autocheck                 # рабочий скрипт: проверка + генерация + замена
```

### UCI-конфиг (`/etc/config/warp-autocheck`)

```
config main
    option enabled '0'          # автопроверка вкл/выкл
    option interval '6'         # часов между проверками
    option interface 'warp'     # имя amneziawg-интерфейса
    option retries '2'          # доп. проверок перед заменой (0–3)
    option conf '/root/WARP.conf'
```

### Рабочий скрипт (`/usr/bin/warp-autocheck`)

Команды:
- `check` — полная проверка интерфейса (см. критерий ниже), результат JSON в
  stdout, подробности в лог;
- `run` — для cron: если включено и прошло N часов с последней проверки —
  `check`, при провале — повторы, при подтверждении — `regen`;
- `regen` — генерация с подбором (порт «Сгенерировать с проверкой» ZM),
  затем замена и перезапуск интерфейса;
- `status` — JSON статуса для LuCI (последняя проверка, результат, замена,
  конфиг есть/нет, интерфейс есть/нет, интервал и т.д.).

Состояние: `/tmp/warp-autocheck.state` (время последней проверки,
счётчик неудач) + лог в logread (`logger -t warp-autocheck`) и
`/tmp/warp-autocheck.log` (хвост для страницы).

### Критерий «конфиг недоступен» (проверка)

Скрипт разбирает Endpoint/PrivateKey из интерфейса (не из файла) и:

1. `awg show <iface> latest-handshakes` — возраст рукопожатия > 180 сек —
   подозрение (совпадает с ZM: у живого туннеля handshake не старше 3 минут).
2. `curl --interface <iface>` на `https://www.cloudflare.com/cdn-cgi/trace`
   (запасные `https://1.1.1.1/cdn-cgi/trace`, ipinfo.io, api.ipify.org).
   Нет внешнего IP → не работает.
3. Если `warp=` из trace отличен от `on/plus` → не работает.
4. `speed.cloudflare.com/meta` → `colo`; если colo в списке российских
   (`DME`, `SVO` и пр. — список из ZM `ST_RU_COLOS`) → не работает.
5. ping-зонд (`_st_warp_probe`-подобный): потери 100% или обрыв потока
   (torn: >= 3 потерянных подряд в конце) → не работает.

Итог проверки: ok / no-link / torn / ru-colo.

### Генерация с подбором (`regen`)

Своя копия логики ZM (`do_awg_gen check`), упрощённая до нужного:

1. **Ключи.** Регистрация в Cloudflare API (`api.cloudflareclient.com`,
   User-Agent okhttp/3.12.1, ключ создаётся на роутере через `awg genkey`).
   Если API недоступен напрямую — обходные пути как в ZM: через внешний
   генератор, через уже живые туннели, через временный туннель на общих
   (boot) ключах.
2. **Подбор точки входа.** Перебор портов × точек входа × масок I1: временный
   amneziawg-интерфейс (`ip link add ... type amneziawg`), `awg setconf`,
   ожидание handshake (до 8 с), затем trace. Победа — первая зарубежная точка,
   где трафик реально идёт и не torn. Лимит времени ~7 минут, максимум ~80
   попыток — как в ZM. Фолбэки: RU-узел → точка с рукопожатием → стандартная.
3. **Замена.** Новый конфиг сначала пишется во временный файл, проверяется
   (`awg setconf` на тестовом интерфейсе), затем атомарно переименовывается в
   `/root/WARP.conf` (chmod 600).
4. **Переприменение.** Обновление endpoint/ключей интерфейса: из WARP.conf
   берутся PrivateKey (для `network.<iface>` —
   `network.<peer_sec>.private_key`... на практике ZM для regen пересоздаёт
   интерфейс; здесь: `uci set private_key/PublicKey/endpoint_*` в
   amneziawg-секции интерфейса + маскировочные параметры Jc/Jmin/Jmax/S1/S2/
   H1..H4/I1, затем `ifup <iface>`). Это путь минимального вмешательства:
   имя, зона firewall и маршруты сохраняются.
5. **Пост-проверка.** Через ~15 сек после ifup — `check` нового интерфейса;
   результат в лог/статус.

Осторожность: regen не запускать, если идёт другая операция (lock-файл
`/tmp/warp-autocheck.lock`).

### rpcd-плагин

Методы ubus (`luci.warp-autocheck`): `status`, `check` (запуск в фоне, статус
через `status`), `regen`, `get_settings`, `set_settings`, `log`. Реализация —
sh-скрипт, вызываемый rpcd (как у ZM: `/usr/libexec/rpcd/warp-autocheck`),
тяжёлые операции — в фоне через `nohup ... &` + lock.

### Страница LuCI

JS view (`www/luci-static/resources/view/warp-autocheck/main.js`), русский
текст. Карточки:
- «Статус» — конфиг есть/нет, интерфейс, точка входа, рукопожатие, последний
  результат проверки (цветной бейдж), последняя замена;
- если конфига нет — ошибка «WARP-конфиг не найден. Сгенерируйте его в Zapret
  Manager (раздел AmneziaWG)» и больше ничего;
- «Настройки» — вкл/выкл, интервал (часы), имя интерфейса, число повторов;
- «Действия» — «Проверить сейчас», «Заменить сейчас» (с confirm), кнопка
  обновления статуса;
- «Лог» — хвост лога.

## Решения из проверки строителем

| Вопрос | Решение |
|---|---|
| Если генерация нашла только RU-узел | RU-выход ПРИЕМЛЕМ для владельца (так YouTube без рекламы) — рабочая RU-точка принимается, замена происходит; смертью считаются только no-link/torn |
| WAN-предпроверка | да: перед `check` и перед `regen` контрольный запрос мимо туннеля; WAN мёртв → статус «сеть недоступна», счётчик неудач не растёт, замены нет |
| Бэкап и откат | перед заменой старый конфиг + UCI-ключи сохраняются (`WARP.conf.bak`); если пост-проверка нового не прошла — один авто-откат, статус «заменён и откачен» |
| Ребут роутера | grace-период: первые 15 мин uptime автопроверка не запускается |
| Внешний генератор ключей | оставить как фолбэк (как в ZM) |
| Гонка с regen в ZM | best effort, не отслеживаем процессы ZM |

## Ограничения

- Требуются пакеты: `amneziawg-tools` (утилита `awg`), `curl`, `jq`/`jsonfilter`
  (jsonfilter входит в OpenWrt), `ip-full` не обязателен (ip link add — из
  `ip-full`? проверить: в OpenWrt `ip` из `ip-tiny` умеет `link add type
  amneziawg` — уточнить при реализации, при необходимости зависимость
  `ip-full`).
- Генерация с подбором занимает до 7–10 минут и на это время поднимает
  временный интерфейс — страница предупреждает.
- Проверка «через существующий интерфейс» считает недоступным и случай,
  когда интерфейс просто выключен пользователем (`option enabled 0` в
  network): автопроверка в этом случае пишет статус «интерфейс выключен
  вручную» и НЕ запускает замену — пользователь сам виноват, надо чинить
  руками. (Анти-цель: не воевать с ручным управлением.)
- Пакет не создаёт интерфейс из WARP.conf. Если интерфейса с указанным именем
  нет — страница показывает подсказку «Импортируйте WARP.conf как интерфейс
  через Zapret Manager или LuCI» и автопроверка стоит.

## Что отдано на откуп разработчику

- Точная реализация uci-обновления интерфейса (какие поля трогать) — по коду
  ZM (`do_awg_regen` / `_awg_iface_set`).
- Формат лога и ротация хвоста.
- Точные формулировки текстов на странице.
- Состав Makefile для SDK-сборки ipk + скрипт-установщик `install.sh`.
- Обработка apk-vs-opkg (OpenWrt 25.12+) в зависимостях.

## Верификация

Автотестов на роутере нет; проверка:
1. `sh -n` на все sh-скрипты; `python3 -c json.load` на JSON-файлы (ACL/menu).
2. Сборка ipk через OpenWrt SDK (или ручная сборка `build-ipk.sh` —
   структурирование control/data и `ipk`-архив) — установка на чистой системе
   не проверяется здесь, проверит пользователь.
3. Статическая проверка соответствия критериев «недоступности» коду ZM.
4. На роутере у пользователя: установка, страница открывается, «Проверить
   сейчас» даёт осмысленный результат, при мёртвом конфиге regen заменяет и
   перезапускает интерфейс.
